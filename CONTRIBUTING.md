# Contributing

Спасибо, что хотите помочь сделать roadmap лучше.

## Принципы

- Один PR — одна логическая правка. Большие переработки сначала обсуждаются в issue.
- Тон: трезвый, прикладной, без маркетинга и академической воды.
- Ресурсы добавляем только проверенные. В описании PR кратко обоснуйте пользу.
- Не ломайте оглавление и якоря разделов. Если меняете заголовок — обновите ссылку в TOC.
- Опечатки и битые ссылки — без issue, сразу PR.

## Как внести правку

1. Сделайте fork репозитория.
2. Создайте ветку: `git checkout -b fix/typo-stage-7` или `feat/add-resource-stage-11`.
3. Внесите правку, проверьте локально, что markdown рендерится корректно.
4. Прогоните `markdownlint` если он установлен.
5. Откройте PR в `main`, заполните шаблон.
6. Дождитесь review. Будьте готовы к обсуждению.

## Что точно примут

- Исправления опечаток и грамматики.
- Обновление устаревших ссылок и версий .NET.
- Добавление проверенных ресурсов с обоснованием.
- Уточнения формулировок без потери смысла.
- Новые этапы и разделы, согласованные в issue.
- Переводы на другие языки в отдельных файлах `README.<lang>.md`.

## Что скорее всего не примут

- Рекламные ссылки и партнёрские курсы без явной пометки и реальной пользы.
- Удаление существующих разделов без замены и аргументации.
- Холивары про фреймворки и редакторы.
- Стилистические правки ради вкусовщины.
- Машинный перевод без вычитки носителем языка.

## Стиль текста

- Короткие абзацы, активный залог, конкретные глаголы.
- Маркированные списки только для перечислений, для аргументов — прозой.
- Код в ```csharp ... ``` блоках с подсветкой синтаксиса.
- Имена технологий с правильным регистром: ASP.NET Core, EF Core, PostgreSQL, Kubernetes.
- Цифры словами от одного до девяти, дальше — цифрами.
